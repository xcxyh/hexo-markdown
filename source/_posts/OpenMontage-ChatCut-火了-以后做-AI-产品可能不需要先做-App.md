最近两个 AI 视频工具很火。

一个叫 OpenMontage，一个叫 ChatCut。

它们最有意思的地方，不是又做了两个 AI 视频编辑器，而是：**你甚至不需要先打开它们。**

你可以直接在 Codex 或 Claude Code 里说：

> 把这段 47 分钟的访谈剪成一分钟，删掉废话，把冲突最大的观点放到开头，再加上字幕和音乐。

接下来，Agent 会自己分析素材、寻找高光片段、调整时间线、生成字幕和动效，最后交付一个可以继续修改的视频。

看到这里，我突然意识到一件事：

> **以后做 AI 产品，可能不一定要先做一个 App。**

你可以直接把自己的产品，变成 Codex 的一种能力。

---

## 这次不只是“用 AI 剪视频”

先简单说下这两个产品。

OpenMontage：
https://github.com/calesthio/OpenMontage

它是一个开源的视频生产系统，可以接入 Codex、Claude Code、Cursor 等 Coding Agent。

用户只需要说自己想做什么，后面的研究选题、写脚本、做分镜、寻找素材、生成配音、剪辑和渲染，都可以让 Agent 继续完成。

OpenMontage 不是只给 Agent 接了几个视频生成 API。

它把视频制作拆成了很多阶段，每个阶段都有工作流程、检查标准和确认节点。

例如，正式生成素材之前，先给出方案和成本；花钱生成之前，让用户确认；视频渲染完成之后，再检查画面、字幕、音量和文件是否正常。

它更像是把一个视频团队的工作方式，写成了一套 Agent 可以执行的说明书。

ChatCut：
https://chatcut.io/

它走的是另外一条路线。

ChatCut 本身就是一个视频编辑产品，有字幕、动效、配音、视频生成和多轨时间线。现在它把这些能力开放给 Codex，让 Agent 可以直接操作一个真正的视频项目。

比如你说“删掉所有口头禅”，它不只是返回一段建议，而是真的修改字幕和时间线。

你说“把结论放到案例前面”，它会直接调整对应的视频片段。

更重要的是，改完之后项目仍然可以继续编辑，而不是生成一个不可修改的 MP4 就结束了。

一个更像开源的视频生产系统，一个更像 Agent 可以调用的视频 SaaS。

但它们背后的逻辑是一样的：

> **Codex 负责理解用户想要什么，产品负责把事情真正做出来。**

---

## 软件正在从“一个 App”变成“一种能力”

以前做视频，用户需要分别打开剪辑软件、字幕软件、图片工具、配音工具。

每个软件都有自己的账号、项目和操作方式。用户为了得到一个结果，需要在不同软件之间来回复制、导出和上传。

真正麻烦的地方，很多时候不是某个功能不会用，而是需要人一直充当这些软件之间的“胶水”。

Agent 出现之后，这套关系开始发生变化。

以前是：

> 用户打开软件 → 学习功能 → 一步步完成操作

现在可能是：

> 用户告诉 Agent 目标 → Agent 选择并调用多个产品 → 直接交付结果

用户面对的不再是一堆软件，而是一个负责理解需求、拆解任务和协调工具的“项目经理”。

至于它背后调用了 ChatCut、FFmpeg，还是某个视频生成模型，普通用户可能根本不关心。

他只关心一件事：

> 我交代的事情，最后有没有做好？

就像今天我们访问一个网站，不会关心它用了哪家云服务一样。

将来我们让 Agent 做一件事，也未必会关心它背后调用了几个软件。

这会带来一个很大的变化：

过去所有软件都在争夺自己的入口，希望用户下载 App、注册账号、每天打开。

未来很多软件可能不再需要成为一个独立入口。它们会退到 Agent 后面，在合适的时候被调用。

软件从一个用户必须进入的“地方”，变成了一种随时可以调用的“能力”。

我觉得这才是 OpenMontage 和 ChatCut 最值得关注的地方。

---

## 真正的护城河，不是接入了多少模型

如果产品只是给 Codex 接几个 API，这件事其实没什么门槛。

视频模型谁都能调用，字幕、配音、图片生成也都有现成服务。

真正困难的是：

- 应该先做什么，后做什么？
- 什么情况下应该让用户确认？
- 应该选择哪个模型，成本是多少？
- 生成失败之后怎么处理？
- 什么样的结果才算专业？

OpenMontage 最有价值的地方，不是它支持了多少视频模型，而是它在尝试把视频团队的经验写进工作流。

什么时候应该先做样片，什么时候应该保留停顿，什么时候应该把冲突提前，什么样的素材放在一起会很奇怪。

这些细碎的判断，才是一个专业剪辑师真正值钱的地方。

换到其他行业也是一样。

一个财务人员知道哪些异常支出值得提醒，哪些变化只是正常波动。

一个销售知道什么样的客户应该马上跟进，什么样的客户没有必要投入太多时间。

一个内容编辑知道什么适合当标题，什么应该放在开头，什么虽然正确但读者根本不会看。

这些经验以前存在人的脑子里，或者藏在公司的 SOP 里。

现在，它们可以被整理成 Agent 能理解的 Skill、工作流和检查标准。

所以以后做垂直 AI 产品，真正的护城河可能不是：

> 我们接入了哪个最新模型。

而是：

> **我们能不能把这个行业里最好的工作方法，变成一套 Agent 可以稳定执行的系统。**

工具是 Agent 的手，模型是 Agent 的脑子，但行业经验才决定它做出来的东西到底专不专业。

---

## 有了 Agent，不代表所有产品只剩一个聊天框

当然，这条路线也不是说，以后所有软件都只需要一个聊天框。

视频就是一个很好的反例。

你可以告诉 Agent“这里节奏再快一点”，但最后还是要亲眼看：字幕有没有挡住人物，音乐进入的时间对不对，两个镜头接在一起舒不舒服。

这些判断很难完全通过文字完成。

所以未来比较合理的产品形态，可能不是聊天界面取代专业界面，而是重新分工：

- 对话负责表达意图
- Agent 负责规划和执行
- 专业界面负责检查和精确调整

ChatCut 仍然保留时间线，就是因为用户需要看到 Agent 到底改了什么，也需要在不满意的时候继续调整。

OpenMontage 也做了一个制作看板，用来展示脚本、素材、成本和执行进度。

它们都没有让 Agent 躲在黑盒里运行半小时，然后突然扔出一个结果。

这点非常重要。

因为用户敢不敢把任务交给 Agent，不只取决于 Agent 有多聪明，还取决于整个过程是否可见、可控。

它准备花多少钱，应该提前告诉我。

它要换一个模型，应该告诉我为什么。

它做了哪些修改，我应该能够看到。

它做错了，应该能够回退。

所以好的 Agent 产品，不是所有事情都自动完成，而是要建立一个合理的信任过程。

先分析问题，给出方案，做一个低成本的样例。用户确认之后再批量执行，完成后由系统检查一遍，人再做最终决定。

这可能没有“一句话全自动生成”听起来那么性感，但它更接近一个真正能长期使用的产品。

---

## 如果现在让我做一个 AI 产品

如果现在让我重新做一个 AI 产品，我可能不会先开发一个完整 App，也不会再做一个万能聊天机器人。

我会先找一件结果明确、但过程非常复杂的工作，然后把它变成 Codex 或 Claude Code 可以调用的能力。

比如，不做一个笼统的“AI 财务助手”，而是：

> 读取一个家庭过去一年的账单、贷款和大额支出，自动生成月度财务分析，并提前提醒未来三个月的现金流风险。

不做一个什么都能写的“AI 内容工具”，而是：

> 把一次访谈自动变成文章、短视频、标题和不同平台的发布版本。

不做一个泛泛的“AI 销售”，而是：

> 开完会以后自动整理客户需求、更新 CRM、生成跟进邮件，并提醒下一步动作。

先把结果定义清楚，再去拆这件事需要哪些工具、哪些数据、哪些专业判断，哪些地方 Agent 可以直接做，哪些地方必须经过人确认。

产品的核心不再是做了多少个功能，而是这条完整链路能不能真的跑通。

我现在越来越觉得，未来 AI 产品的机会，可能不在于再做一个更聪明的聊天框。

而在于找到那些现在还需要人不断复制、粘贴、切换软件、检查结果的工作，把它们变成 Agent 可以独立完成的任务。

---

## 这条路线也有明显的问题

当然，我不认为所有 AI 产品最后都会变成 Codex 插件。

首先，这类产品会非常依赖 Codex、Claude Code 这些平台。

如果平台调整插件规则、权限或者收费方式，依附在上面的产品都会受到影响。

其次，Agent 能把流程跑起来，不代表结果一定专业。

尤其是视频、设计、内容这些主观性很强的领域，最后仍然需要人判断。

还有一个现实问题是，并不是所有用户都在使用 Coding Agent。

对很多普通用户来说，打开一个功能清楚的 App，可能仍然比安装 Skill、配置 Agent 更简单。

所以我觉得 App 不会消失。

更可能的结果是，一个产品同时存在两种入口：

- 普通用户直接打开 App
- 重度用户让 Agent 调用产品能力

ChatCut 现在其实就是这种形态。它既有自己的编辑器，也可以被 Codex 调用。

这样既不会完全依赖某一个 Agent 平台，也能提前进入新的分发渠道。

---

## 最后

OpenMontage 和 ChatCut 现在还只是两个视频产品，但它们让我看到了一种可能：

未来的软件不一定都需要成为用户主动打开的地方。

很多软件会退到 Agent 后面，成为完成某项任务时被临时调用的一种能力。

到那时，产品竞争的可能不再是谁的功能更多，而是谁能让 Agent 更稳定、更专业地把事情做完。

如果未来用户每天面对的只有 Codex、Claude Code，或者某个通用 Agent，那么今天这些独立 App，最后会变成什么？

这个问题，可能比“下一个 AI App 应该做什么”更值得思考。
